# tree-sitter-dshl

Tree-sitter grammar for DSHL, the shader language of the Dagor Engine. The repository is public.

## Reference

- The authority is the shader compiler in `prog/tools/ShaderCompiler2/` of the Dagor tree: `shlex.dlp` (the lexer),
  `shsyn.whl` (the grammar), `shlexterm.cpp` and `shMacro.cpp` (includes and macros), and `codeBlocks.cpp` (the `##`
  directives of HLSL text). Settle each grammar question in that code. The DSHL reference in
  `_docs/source/api-references/dagor-dshl/` names the constructs.
- The grammar is a clean-room implementation. No file, rule, or test comes from another DSHL grammar, such as the ANTLR
  grammar of GaijinEntertainment/Dagor-Shader-Language-Server. Do not read one when you change this grammar.
- An input that the compiler accepts parses without ERROR or MISSING nodes, except for the limits below. An input that
  the compiler rejects produces ERROR wherever the grammar can see the defect.
- The grammar does not expand includes or macros, and a macro parameter can stand for any token. These are its limits;
  keep the list current:
  - Each statement parses in each body: the file, a shader, a block, a preshader block, and a macro body. The compiler
    checks the context of a statement after the macro expansion, and a macro body takes the statements of its call
    site. The render pass, subpass, and framebuffer layout bodies keep their own statements.
  - Where the compiler takes a number, a string, or a type suffix, the grammar also takes an identifier, because a
    macro parameter can stand there. An identifier alone is a statement (`parameter_statement`) for the same reason.
  - A macro body is a sequence of statements or one condition. A body that is neither, and whose braces or parentheses
    do not balance or which is a comma-separated list, is one `macro_fragment` token.
  - An `include` inside a declaration gives ERROR, as in `prog/gameLibs/render/shaders/debugGbuffer.dshl`.
- The grammar holds no platform names. A name after `hardware.` is an identifier.

## Where things live

- `grammar.js` - statements, conditions, and preshader expressions.
- `src/scanner.c` - the braces and the text of an HLSL block (`hlsl_code`), the end of a `##if`, `##elif`, `##bool`,
  or `##declare` line, the raw arguments of `##assert`, and the `macro_fragment` scan.
- `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/` - generated by `tree-sitter generate`
  with tree-sitter CLI 0.27.1. Never edit them by hand. Regenerate with that CLI version, and make a CLI upgrade its own
  change, which also moves the `tree-sitter-ref` of the CI workflow, the `TREE_SITTER_CLI_VERSION` and
  `TREE_SITTER_CLI_SHA256` of the publish workflow, the `tree-sitter-cli` of `package.json`, and the `tree-sitter`
  dev-dependency of `Cargo.toml` with its docs link in `bindings/rust/lib.rs`: CI regenerates the parser and fails on a
  difference.
- `queries/highlights.scm` - editor highlighting. `test/highlight/` holds its capture assertions.
- `queries/injections.scm` - HLSL in the text of an HLSL block and in the arguments of `##assert`.
- `queries/tags.scm` - the definitions and references for code navigation (`tree-sitter tags`). `test/tags/` holds
  its tag assertions.
- `bindings/`, the package manifests (`binding.gyp`, `Cargo.toml`, `CMakeLists.txt`, `go.mod`, `Makefile`,
  `package.json`, `Package.swift`, `pyproject.toml`, `setup.py`), `.editorconfig`, `.gitattributes`, and `.gitignore` -
  generated by `tree-sitter init` from `tree-sitter.json`. Run `tree-sitter init --update` after a change to
  `tree-sitter.json` or a CLI upgrade, and set the version with `tree-sitter version <version>`.
- `package-lock.json`, `Cargo.lock`, `go.sum`, `Package.resolved` - lockfiles that npm, cargo, go, and swift write when
  they resolve the dependencies of the manifests. Commit them with the manifest change.
- `.github/` - the CI and publish workflows, dependabot, and issue templates. The publish workflow authenticates to
  crates.io, PyPI, and npm with trusted publishing and holds no registry token.
- `eslint.config.mjs` - the lint configuration for `grammar.js` (`npm run lint`).
- `examples/` - DSHL files that the CI workflow parses.
- `test/corpus/` - corpus tests, one file per topic. `:error` marks an input that must produce ERROR.

## Rules

- A node kind and a field take the name that the DSHL reference gives the construct: `preshader_block`,
  `type_suffix`, `refined_block_tag`, `interval_declaration`. A construct that the reference does not name takes the
  name of the compiler grammar in `shsyn.whl`, with each abbreviation spelled out: `sh-if-stat` is `if_statement`,
  `external-variable` is `preshader_variable`, and `hlsl-compile` is `compile_statement`.
- `_statement`, `_condition`, and `_expression` are the supertypes.
- The docs cite a Dagor file only when GaijinEntertainment/DagorEngine on GitHub has it.
- The compiler reads the HLSL text of a block to the `}` that closes it, and skips braces in comments and in strings.
  A line whose first characters are `##` and one of `if`, `elif`, `else`, `endif`, `bool`, `declare`, or `assert` is a
  directive; `##` elsewhere, as in a `#define` that joins tokens, is HLSL text.
- The scanner returns `macro_fragment` only at the start of a macro body, and reads to `endmacro` before it decides.
  Its scan skips comments, strings, and the text of HLSL blocks, like the lexer of the compiler.
- The scanner never returns an HLSL token in error recovery: `_error_sentinel` is valid only there.
- Model the repository setup (workflows, lint, lockfiles, README) on the official grammars of the tree-sitter
  organization, such as tree-sitter/tree-sitter-cpp. `README.md` holds only the badges, a short description of the
  grammar, the meaning of the version numbers, and references. Editor setup, binding use, and maintainer procedures
  stay out of it.
- `tree-sitter init` writes only the first author of `tree-sitter.json` into a package manifest. Keep the full author
  list in `package.json`, `Cargo.toml`, and `pyproject.toml` by hand; `tree-sitter init --update` keeps it.
- CLI 0.27.1 `tree-sitter init --update` writes a second `let dir` line into `Package.swift`, and rewrites
  `tree-sitter.json` with `injection-regex` after the queries and without its final newline. Remove that line, and
  revert `tree-sitter.json`.
- The MinGW branches of the `install` and `uninstall` rules in `Makefile` differ from the CLI template; keep them.
- Keep the `externals` array in `grammar.js` and `enum TokenType` in `src/scanner.c` in the same order.
- The generator copies the fields of an aliased hidden rule into the parent node. A rule that has fields and appears
  only under an alias gets a visible name, as `last_interval_value` does.
- In `queries/highlights.scm`, a later pattern overrides an earlier one in both tree-sitter-highlight and Neovim. Put a
  specific pattern after the general pattern, and give each pattern one capture.
- A `#match?` regex must mean the same in Rust regex syntax and in Vim very-magic syntax (Neovim).
- In `queries/tags.scm`, tree-sitter-tags keeps one tag per name node, from the earliest pattern that matches it. Put
  a specific pattern before the general pattern for the same node.
- A workflow pins each action to the commit SHA of a release and names the release in a comment
  (`actions/checkout@<sha> # v7.0.1`), which Dependabot reads to update both. A checkout sets
  `persist-credentials: false`.
- A change reaches `main` through a pull request, merged by squash or rebase after the `ci-ok` job of
  `.github/workflows/ci.yml` passes; the `protect-main` ruleset rejects a direct push. Add each new CI job to the
  `needs` list of `ci-ok`.

## Releasing

- The version is a semantic version of the grammar. A major release renames or removes a node kind or a field, a minor
  release adds node kinds, fields, or syntax, and a patch release corrects the trees or the queries. The supertypes
  and the `required` and `multiple` flags of `src/node-types.json` are not part of that promise. The `Versioning`
  section of `README.md` gives the users this rule; change it with this rule.
- To release, set the version with `tree-sitter version X.Y.Z`, then run `tree-sitter generate`, because
  `src/parser.c` holds the version too, and update the lockfiles with `cargo update --workspace --offline` and
  `npm install --package-lock-only --ignore-scripts`. Commit, and push the tag `vX.Y.Z`.
- The Go module path ends in `/vX` from major version 2, as Go requires. A new major version changes the path in
  `go.mod` and in the import of `bindings/go/binding_test.go`.
- The tag starts `.github/workflows/publish.yml`. It checks that the tag matches `tree-sitter.json` and the Go module
  path, creates the GitHub release with attested artifacts, and publishes to crates.io, PyPI, and npm. A registry that
  already has the version is skipped. The Go module needs no publish step: the tag on the public repository is the
  release.
- A manual run of `publish.yml` rehearses a release: it runs the checks and builds every artifact, and publishes
  nothing. Run it after a change to the workflow.
- The `protect-release-tags` ruleset forbids moving or deleting a `v*` tag. When a publish job fails for a reason
  outside the repository, run the failed jobs again; when the fix is a commit, release the next version.
- crates.io, PyPI, and npm each hold a trusted publisher for the repository `GaijinEntertainment/tree-sitter-dshl`, the
  workflow `publish.yml`, and the environment `crates`, `pypi`, or `npm`. The three environments accept deployments
  only from `v*` tags. A new name for the repository, the workflow file, or an environment needs a new trusted
  publisher on each registry.
- A job that can mint an OIDC token (`id-token: write`) runs only GitHub's own actions and the registry's own publishing
  action. The publish workflow downloads the tree-sitter CLI and checks its SHA-256 for that reason.

## Verification

- After a change to `grammar.js` or `src/scanner.c`, run `tree-sitter generate` and `tree-sitter test` in this
  directory, and commit the regenerated `src/` files with the change. After a change to `grammar.js`, also run
  `npm run lint`.
- After a change to `grammar.js` or `src/scanner.c`, also parse every DSHL file of a Dagor checkout. Run these commands
  from the root of the checkout, with `GRAMMAR` set to the directory of this grammar:

  ```sh
  git ls-files '*.dshl' > /tmp/dshl-files.txt
  tree-sitter parse --grammar-path "$GRAMMAR" --paths /tmp/dshl-files.txt --quiet --stat
  ```

  Only these files may fail: `prog/gameLibs/render/shaders/debugGbuffer.dshl` (an include inside a declaration),
  `prog/daNetGame/shaders/forward_postfx.dshl` (a comma before the `)` of a vector expression, which `shsyn.whl` does
  not take), `prog/samples/commonShaders/ssr_temporal_ue4.dshl` (HLSL, no DSHL), the shader templates
  `prog/gameLibs/webui/plugins/shaderEditors/*Template.dshl` (placeholders in place of names), and the test inputs of
  the colorer in `_tests/colorer/`.
- `tree-sitter fuzz` parses each corpus input again after random edits and their undo, and compares the tree with a
  fresh parse. Run it after each change to the scanner.
- Write the expected tree of a new corpus test with its field names. `tree-sitter test --update` writes a new tree
  without them, and the test then ignores the fields.
- After a change to a query, run `tree-sitter test`, which runs the assertions in `test/highlight/` and `test/tags/`.
- The CLI caches one compiled parser per grammar name. After you parse with another grammar named `dshl`, such as a
  copy at another revision, pass `--rebuild` to `tree-sitter test`.
- After a change to `tree-sitter.json`, `bindings/`, or a package manifest, build and test each binding in a copy of
  this directory, so that no build output lands in the tree: `cargo test`, `make && make test`, `go test ./...`,
  `npm install && npm test`, `swift test`, and `python -m unittest discover -s bindings/python/tests` after
  `pip install -e ".[core]"`.

## Public repository

- Keyword lists, tests, and examples hold no platform names, such as the platform values of `hardware.`. Some platform
  names are confidential.
- Files and commit messages hold no internal context: no internal hosts, no links to internal Gerrit changes or tracker
  issues, and no local paths. Cite a source only when it is public on GitHub.
